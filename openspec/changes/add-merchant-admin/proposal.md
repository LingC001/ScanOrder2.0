# 商家后台首版

## Why

当前菜品、分类和订单能力分散在移动端与命令行中，分类只是商品上的自由文本，商家无法独立维护菜单或处理订单，外露的上传页面和无归属订单查询也不适合业务运营。需要建立受控的商家后台，同时保留顾客点餐与查单体验。

## What Changes

- 新增 `/admin` 单商家后台，提供登录、商品管理、分类管理和订单管理。
- 商品使用独立分类实体，支持分类排序，以及商品新增、编辑、上下架、归档和恢复。
- 商家可筛选订单，执行接单、完成和取消，并处理并发状态冲突。
- 顾客首次进入默认弹出固定账号登录窗，只可查询该账号在功能上线后创建的订单。
- **BREAKING** 移除移动端 `/upload` 页面与公开新增菜品接口，菜品维护迁移至商家后台。
- 新增显式数据库迁移，将现有分类文字转换为分类记录，并为库存与订单补充状态和归属。

## Capabilities

### New Capabilities

- `account-sessions`: 商家与固定顾客账号的独立登录、退出、访问控制和会话边界。
- `merchant-admin`: 商家后台中的分类、商品及订单管理能力。

### Modified Capabilities

- `menu`: 顾客登录后展示按独立分类排序的在售菜单。
- `ordering`: 订单增加顾客归属和可处理状态，顾客只查询自己的订单。
- `food-media`: 菜品图片仅由已登录商家在后台新增或替换。

## Impact

影响 `apps/web` 路由与界面、`apps/api` 认证及商品分类订单接口、`packages/contracts` 公共类型、PostgreSQL 迁移、旧菜品导入、Harness 与 Playwright 业务链路。支付、退款、员工账号和顾客自助注册不在本次范围内。
