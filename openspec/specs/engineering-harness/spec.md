# 工程 Harness 规范

## Purpose

为 ScanOrder 的开发者与编程 Agent 提供可发现的工程知识、可执行的依赖与文档约束，以及能保留实际证据的验证入口，使复杂任务从规范到实施和归档保持一致并避免将未执行检查误报为通过。

## Requirements

### Requirement: 工程上下文可发现

工程 SHALL 提供根指引、局部职责、架构地图和知识索引，能够定位当前启动方式、接口、规范和验证工具。

#### Scenario: 新任务定位依据

- **WHEN** 开发者或 Agent 从根指引进入仓库
- **THEN** 能通过有效本地链接找到架构、运行说明、领域文档和规范入口

### Requirement: 工程边界可自动检查

工程 SHALL 自动检查前后端源码边界、共享包平台无关性、包与后端业务模块公开入口、应用内运行时循环、控制器持久化依赖及文档链接，并对失败提供文件位置与修复提示。

#### Scenario: 非法依赖失败

- **WHEN** 前端引用后端源码或控制器直接导入实体
- **THEN** 架构检查返回非零退出码并指出违反的规则

#### Scenario: 业务模块的私有入口与循环

- **WHEN** 后端模块越过公开入口访问域内源码，或应用源码产生运行时循环
- **THEN** 检查返回非零退出码并指出引用路径，已登记的 ORM 注册和关系依赖可按规则使用

#### Scenario: 文档目标失效

- **WHEN** 文档链接指向不存在的仓库内文件
- **THEN** 文档检查返回非零退出码并指出来源与目标

### Requirement: 验证结果可追溯

工程 SHALL 提供基础和完整验证入口，记录每步耗时和退出码，失败停止后续步骤，并保存本地报告。

#### Scenario: 子步骤失败

- **WHEN** 任一必要检查失败或子进程无法启动
- **THEN** 统一入口返回非零退出码，报告标记失败并保留已执行步骤，后续步骤不运行

#### Scenario: 完整业务回归

- **WHEN** 执行完整验证
- **THEN** 基础检查通过后执行隔离真实 PostgreSQL 集成测试及 Chromium 浏览器回归

#### Scenario: 生成文档时临时实例无法启动

- **WHEN** 临时 PostgreSQL 初始化或在就绪前退出
- **THEN** 生成检查返回非零退出码，并记录失败阶段、可取得的数据库原始诊断和清理结果

### Requirement: 规范驱动任务生命周期

工程 SHALL 使用项目固定的 OpenSpec 和中文技能管理复杂任务，使制品、实施任务、实际验收证据及正式规范可被后续任务发现。

#### Scenario: 完成后归档

- **WHEN** 已授权任务完成且相关验收通过
- **THEN** 增量规范同步到正式规范，变更及其任务和验收记录归档，未运行的远端检查明确标注

### Requirement: 持续集成复用本地入口

工程 SHALL 在 push、PR 和手动触发时执行 Windows／Ubuntu 基础检查，保存日志和测试证据。需要启动临时 PostgreSQL 的生成文档检查及数据库、浏览器回归在 Ubuntu CI 执行。

#### Scenario: 自动检查失败

- **WHEN** 任一 CI 检查失败
- **THEN** 对应作业失败，并上传已产生的日志和测试报告供定位

#### Scenario: 托管 Windows 基础检查

- **WHEN** CI 在 GitHub 托管 Windows 上运行基础验证
- **THEN** 执行无需启动数据库的跨平台检查，生成文档校验由同次运行的 Ubuntu 基础作业执行

### Requirement: 增量归档兼容性

工程 SHALL 将活动增量与当前正式规范之间的可检测归档冲突纳入规范验证。

#### Scenario: 增量覆盖已演进要求

- **WHEN** 活动增量新增了名称已存在且内容不同的正式要求
- **THEN** 规范检查返回非零退出码并指出冲突增量

### Requirement: CI 结果汇总

工程 SHALL 汇总基础验证、数据库、浏览器和隔离观测作业的结果。

#### Scenario: 有作业未成功

- **WHEN** 任一基础、数据库、浏览器或隔离观测作业未成功
- **THEN** 汇总作业标记失败，并列出各作业的结果
