# 点餐接口

所有 JSON 接口使用 `/api` 前缀。UUID 字段为 `id`，金额字段以 `Cents` 结尾，单位为人民币分。接口直接返回业务对象或数组，不使用旧 `_id` 或额外 `data` 包装。时间为 ISO 8601，前端按北京时间展示。

## 菜品

`GET /api/foods` 返回菜品数组，字段为 `id`、`category`、`name`、`description`、`imageUrl`、`priceCents`、`recommended`。同一菜名允许出现多次，以 ID 区分。

`POST /api/foods` 使用 multipart，字段为：

| 字段          | 内容                                   |
| ------------- | -------------------------------------- |
| `category`    | 1至50字                                |
| `name`        | 1至100字                               |
| `description` | 1至1000字                              |
| `priceCents`  | 0至10000000之间的整数分                |
| `recommended` | 明确的 `true` 或 `false`               |
| `image`       | 1张真实 JPEG、PNG、WebP 图片，最大5 MB |

成功返回201及新增菜品，图片通过返回的 `imageUrl` 访问。不实现菜品详情、修改、删除占位接口。

## 订单

`POST /api/orders` 请求示例：

```json
{
  "tableNumber": "3111",
  "guestCount": 3,
  "comment": "少辣",
  "items": [{ "foodId": "a151b3fc-9597-4cc6-ad25-9ba712978c78", "quantity": 2 }]
}
```

桌号为1至32字，人数为1至5，备注最多50字，菜品列表为1至100种，单品数量为1至999。同一菜品 ID 不能重复，客户端不得提交总价、菜名或其他额外字段。

服务端使用数据库当前价格计算金额并事务保存。返回201及完整订单：`id`、`location`、`tableNumber`、`guestCount`、`comment`、`items`、`totalAmountCents`、`totalQuantity`、`finished`、`createdAt`、`updatedAt`。

`items` 是下单时的快照，包含 `id`、`foodId`、`name`、`imageUrl`、`priceCents`、`quantity`、`totalAmountCents`。后续菜品导入更新名称或价格，不会改变历史订单。

`GET /api/orders` 返回按下单时间倒序排列的完整订单数组。`GET /api/orders/:id` 返回订单详情。无效 UUID 返回400，合法但不存在的 UUID 返回404。

订单延续原项目的模拟完成逻辑，创建成功后 `finished=true`；不代表真实支付结果。没有订单修改、删除、支付或取消接口。

## 错误

错误使用 NestJS 标准 HTTP 错误响应，主要字段为 `statusCode`、`message`、`error`。`message` 可能是文字或校验错误数组。无效输入返回400，超出上传大小返回413，服务端故障返回500。上传后的数据库保存失败会清理新文件，订单明细保存失败会回滚整张订单。
