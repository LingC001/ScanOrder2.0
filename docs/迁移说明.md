# MongoDB 菜品迁移

只读取导出的菜品 JSON 和原上传图片，只写入新 PostgreSQL 及其上传目录；不会连接或修改原 MongoDB，不导入历史订单。

## 准备数据

从原 MongoDB 导出 `foods` 集合，例如：

```powershell
mongoexport --uri "mongodb://127.0.0.1:27017/ScanOrder" --collection foods --jsonArray --out "C:\data\foods.json"
```

工具兼容 JSON 数组及 mongoexport 默认的 JSON Lines 格式，支持 UTF-8 BOM。每条记录需要这些原有字段：

```json
{
  "_id": { "$oid": "64a000000000000000000001" },
  "category": "纸巾",
  "name": "餐巾纸",
  "price": 1.29,
  "description": "一包",
  "image": "http://原服务/images/纸巾.png",
  "recommended": false
}
```

`_id` 也可为24位十六进制字符串。价格可为普通数字、金额字符串或 Extended JSON 数字，必须为非负金额，最多两位小数；转换为整数分后保存。推荐值支持布尔值及明确的 `"true"`、`"false"` 字符串。

准备原后端上传图片目录。工具按 `image` URL 最后一级文件名查找该目录中的文件，支持中文及 URL 编码文件名。工具不从旧图片服务器下载文件，也不通过旧服务器地址推断数据库位置。

## 预检和导入

```powershell
pnpm --filter @scanorder/contracts build
pnpm data:import --file "C:\data\foods.json" --images-dir "C:\data\upload" --dry-run
pnpm db:migrate
pnpm data:import --file "C:\data\foods.json" --images-dir "C:\data\upload"
```

相对输入路径以项目根目录为基准。`--dry-run` 不需要数据库连接，不写入数据库或上传目录。

预检会检查全部记录、重复旧 ID、字段长度、金额、图片是否存在及真实文件类型，汇总错误并终止，避免只导入部分菜品。支持 JPEG、PNG、WebP，单张不超过5 MB。原素材中有 `.png` 扩展名但实际为 JPEG 的文件，导入后按真实类型保存。

正式导入采用 PostgreSQL 事务。旧 `_id` 保存为唯一 `legacyId`，菜品使用新的 UUID；重复运行会更新同一记录，保留其 UUID，不删除数据库中额外的菜品。图片采用内容摘要命名，相同图片不重复复制，引用重写为 `/images/摘要.扩展名`。失败时回滚数据库，并清理本次创建且没有记录引用的图片。

记录的图片更换后，旧图片会保留，避免误删其他数据的引用。后续可通过离线维护处理无引用文件，本次不增加自动清理业务。
