# ScanOrder Monorepo 重构方案

## 目标与范围

在 `C:\workspace\Study\ScanOrderNew` 中重新组织和实现项目，原项目保持不变。

以原 Vue 2 版本的完整功能为基准，仅实现已有的移动端 H5 功能：人数选择、分类选菜、推荐菜品、图片预览、购物车、备注下单、订单列表、订单详情、商家信息、菜品上传。保留原有橙色风格、布局及图片素材，不扩展商家后台、登录、真实支付或二维码管理。

数据库改为 PostgreSQL，只迁移菜品及其图片；历史订单不迁移，新接口无需兼容旧客户端。

## 工程与前端

- 使用 **pnpm workspace**，划分 `apps/web`、`apps/api`、`packages/contracts`，分别承载前端、后端和共享接口类型。
- 前端采用 **React 19 + TypeScript + Vite + Tailwind CSS 4 + React Router**；后端采用 **NestJS 12 + TypeORM + PostgreSQL 18**，使用 Nest 官方支持的数据库集成方式。[参考](https://docs.nestjs.com/techniques/database)
- 根目录统一提供安装、开发、构建、类型检查、代码检查、测试、数据库迁移和菜品导入命令；依赖版本写入统一锁文件。
- 保留原有七个页面及路由名称。宽屏仅居中展示 H5，不增加桌面布局。
- 使用 Context + reducer 管理人数、购物车和备注，维持原有内存状态方式；购物车按菜品 ID 区分商品，修复同名菜品合并问题。
- 统一商家信息和默认桌号，默认桌号采用首页已有的 `3111`，人数选择贯通页面展示和订单提交。
- 抽取原风格的按钮、导航栏、弹窗、购物车抽屉和表单组件；修复分类切换、空购物车提交、重复点击提交和失败反馈问题。

## 后端与接口

仅提供现有业务需要的接口：

| 接口                    | 行为                                  |
| ----------------------- | ------------------------------------- |
| `GET /api/foods`        | 查询菜品，供前端生成分类和推荐列表    |
| `POST /api/foods`       | 通过 multipart 表单上传图片并新增菜品 |
| `POST /api/orders`      | 创建订单，返回已保存的订单            |
| `GET /api/orders`       | 按下单时间倒序查询订单                |
| `GET /api/orders/:id`   | 查询订单详情                          |
| `GET /images/:filename` | 访问菜品图片                          |

- 共享菜品、购物车及订单请求/响应类型，统一使用 `id`、`description`、`imageUrl`；移除旧 `_id` 等字段依赖。
- 金额统一使用整数“分”，字段明确命名为 `priceCents`、`totalAmountCents`，前端格式化为人民币金额。
- 创建订单只提交菜品 ID、数量、桌号、人数和备注；服务端查询实际价格，计算总价，并在事务中保存订单及菜品快照。
- 延续原有模拟下单行为：提交成功后订单标记完成、清空购物车并进入订单列表，不接入支付服务。
- 上传图片限制为 JPEG、PNG、WebP，最大 5 MB；使用生成的文件名，保存成功后返回相对图片地址。数据库保存失败时清理本次上传文件。
- 配置数据库连接、端口和上传目录的环境变量；前端开发环境代理 `/api` 和 `/images`，移除原服务器地址硬编码。
- 不实现原后端中尚为占位代码的修改、删除等接口。

## PostgreSQL 与菜品迁移

- 建立菜品、订单、订单明细三张表，使用 UUID 主键；菜品分类继续保存为字符串，订单明细保留下单时的名称、图片和价格快照。
- 使用显式数据库迁移维护表结构，关闭自动同步；提供 PostgreSQL Docker Compose 开发配置。
- 提供菜品导入命令，参数指定 MongoDB 导出的 JSON 和原上传图片目录，兼容 JSON 数组、JSON Lines 以及 `_id.$oid`。
- 将原菜品价格从元转换为分，通过旧 MongoDB ID 标识已导入记录，重复执行时更新同一菜品，避免产生重复数据。
- 按原图片地址中的文件名定位图片，复制至新上传目录并重写引用。先预检全部记录和图片，遇到坏数据或缺图时输出明细并中止导入。
- 导入过程不修改源 JSON、原图片及 MongoDB，不导入历史订单。

## 验证与默认约定

- **前端**：验证分类切换、同名菜品、数量增减、清空购物车、备注、提交失败保留购物车、成功后清空及订单详情。
- **后端**：验证金额计算、空订单、非法数量、不存在的菜品、无效订单 ID、图片类型和大小限制、订单事务回滚。
- **迁移**：验证两种 JSON 格式、金额转换、中文文件名、缺图报告以及重复导入不增重。
- **端到端**：在真实 PostgreSQL 上完成“导入菜品 → 选菜 → 下单 → 查看订单详情”，并验证上传的新菜品能够显示。
- **界面验收**：在 375、390、430 像素宽度下对照原界面检查布局、滚动、底部操作栏和弹窗；完成构建、类型检查及相关测试。
- 默认支持 Safari 16.4+、Chrome 111+ 的 H5 环境，与 Tailwind CSS 4 的浏览器要求一致。[参考](https://tailwindcss.com/docs/compatibility)
- 交付中文启动、环境配置及导入说明。真实菜品 JSON 和上传图片目前不在项目目录中，实际迁移以提供的文件为输入；在此之前使用迁移样例验证工具。
