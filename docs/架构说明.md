# 架构说明

## 模块边界

| 模块      | 职责                                  | 主要入口                                                                                                        |
| --------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Web       | 页面、购物车状态、API 调用            | [路由](../apps/web/src/App.tsx)、[请求封装](../apps/web/src/api.ts)、[购物车](../apps/web/src/CartProvider.tsx) |
| API       | 入参校验、业务逻辑、数据与图片保存    | [启动](../apps/api/src/main.ts)、[应用工厂](../apps/api/src/app.ts)、[根模块](../apps/api/src/app.module.ts)    |
| Contracts | 共享请求/响应类型、金额工具、商家信息 | [共享定义](../packages/contracts/src/index.ts)                                                                  |
| Database  | 实体、显式迁移、连接配置              | [数据源](../apps/api/src/database/data-source.ts)、[数据库结构](generated/db-schema.md)                         |
| Import    | 菜品 JSON 与图片的预检、幂等导入      | [导入实现](../apps/api/src/import/foods-importer.ts)                                                            |

Web 和 API 都依赖 Contracts；共享包不应反向依赖应用。浏览器通过 HTTP 调用 API，不直接访问数据库。开发环境由 Vite 代理 `/api` 和 `/images`，生产部署要求见根 README。

API 按 Nest 模块组织。`AppModule` 负责组装应用，`FoodsModule`、`OrdersModule` 分别承载菜品和订单的控制器与服务，`DatabaseModule` 管理共享连接。`main.ts` 调用 `startApplication` 启动服务。`app.ts` 的 `createApplication` 注册全局校验和静态图片路由，集成测试通过同一工厂注入隔离数据库。

## 关键数据流

1. 页面请求菜品列表，以菜品 UUID 维护购物车，分类和推荐列表由菜品数据生成。
2. 提交订单时发送菜品 ID、数量、桌号、人数和备注。
3. API 校验输入，读取数据库当前价格，计算整数分金额，在同一事务内保存订单和明细快照。
4. 成功后前端清空购物车并进入订单列表；历史订单展示保存的快照。

图片上传经真实文件类型和大小校验后写入上传目录，数据库保存图片 URL；数据库写入失败时清理本次上传文件。旧菜品导入以 `legacyId` 识别同一条记录，细节见 [图片与菜品导入](product-specs/food-media.md)。

## 当前业务边界

购物车状态只存在于当前页面会话的内存中。订单创建后标记 `finished=true`，属于模拟完成逻辑。登录、真实支付、菜品编辑/删除和完整商家后台尚未实现。接口字段与约束见 [共享类型](../packages/contracts/src/index.ts) 和对应控制器与 DTO。
